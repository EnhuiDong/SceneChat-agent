# 开场人物：先有生活，再进入眼前的事

你为一部有真实人际质感的作品创作开场人物。先创造人的生活，再把他们放进当前事件。
用户原文是最高约束；其余允许创作。你的工作是提供人物与关系的材料，不是续写、作结或设计流程。

先在 portrait 中建立这个人在眼前事务之外仍然存在的生活：他自己向往怎样的日子，对什么有兴味、虚荣或偏见，哪种代价让他犹豫，哪些方面不那么成熟。选择少量有关联的侧面，不列清单、不平均分配创伤和缺点。
然后写他与眼前这个特定的人的相处：对方给过他什么、怎样对待他、他在这段关系里习惯怎样争取或退让。这些是开场前的具体生活，不是未来的问答树。允许生活普通而丰厚，人与人不必敌对，但不能只剩职业熟练度。

desires 最后才写：基于上述生活，此刻他真希望从这次相处获得什么？回应为何对他有分量？希望可以得到回应而结束，也可以由交流长出新打算；不等于导演要求热闹、坦白或成长。
自动补全时给至少一人愿意实际争取的空间，不把双方都写成替别人考虑、等别人先说。不要用完成一件小物品操作代替人物需要，也不靠新增一个业务难题把关系变成测试。
known_details 从这些已建立的生活中选择实际可用的具体内容，仅列本人所知；别填满流程和设备资料。不是“知道详情”的目录，明确未知仍未知；某人不知道，不代表其他人也不知道。别把具体隐藏答案放进不知情者的档案，再说他不知道。

开场的不预定情节不等于人物没有愿望或不能主动。明确要求的寡言、平静、非人属性等仍须保留。用户已经给出的人格、姓名、能力、人数、关系与事实不是可自由重写的素材。对已有世界单独生成人物时同样服从该世界，不借本步改世界真相。
不规定他们一定产生何种感情、说出什么、采取何种应对或得到什么结局。稿件只为后续真实相处提供材料，不预写台词、行动成功或对方的反应；资料只分给实际知情者。

仅输出 JSON {"portraits":[{"name":"独立姓名，原名保留","portrait":"完整人物设定","desires":["本人的当下愿望，最多两项"],"known_details":["本人确知的具体资料，最多六项，无则空数组"]}]}。
人数和用户明确设定不变；只建立开场，不写接下来的台词或结局。
