# 提示词分布与修改入口

SceneChat 不把所有模型任务合并成一个总提示词。设定生成负责忠实地建立运行条件；角色提交行动意图；旁白呈现结果；引擎负责真正的执行和结束判定。

## 建议阅读顺序

| 文件 | 职责 | 如何生效 |
| --- | --- | --- |
| `scenechat/prompts/actor.md` | 角色如何利用已知信息推进未完成事项、避免重复观点、选择真实行动 | 每次角色生成的提示词开头 |
| `scenechat/prompts/dialogue.md` | 当场回应、潜台词、态度连续性与跨题材表达示例 | 与 actor.md 一起加载；用户指定的文风与人设优先 |
| `scenechat/prompts/scene_actor.md` | 更精简的场景表演合同，不附加数字化事项工作单 | 仅 `actor_prompt_style: scene_first` 实验模式；不是默认替换 |
| `scenechat/prompts/performance.md` | 先表演人物当场的选择、台词与动作，不填写状态记账字段 | 仅 `performance_first` 模式额外调用；默认不启用 |
| `scenechat/prompts/characters.md` | 人物的具体牵挂与选择差异，避免整组变成会议职能 | 结构化人物生成；不附带世界流程与节点设计任务 |
| `scenechat/prompts/narrator.md` | 旁白的权限、证据要求、何时跳过、不能伪造的结果 | 每次旁白生成的提示词开头 |
| `scenechat/prompts/scenario.md` | 详细/简短输入的补全边界、机制闭合与节点设计 | 世界结构化生成；人物入口使用 characters.md |
| `scenechat/prompts/execution_design.md` | 完成事项、独立决策者、实际效果与结束边界的因果设计；多人确认/合作行动示例 | 世界生成与定向修复的运行合同，不进入演员台词 |
| `scenechat/prompt_library.py` | 加载上述文件；生成角色工作单、眼前交流和旁白的引擎事实 | 只从本地状态构造上下文，不调用额外模型 |

修改 Markdown 后重启后端；提示词加载有进程内缓存。这里只写模型行为约束，不修改 JSON 字段名称或引擎允许的操作。模型、供应商和密钥仍由 `.env` 配置。

初始设定须区分作者所知、人物开场所知与未来要求：尚未告知的通知、准备和秘密放在真实知情者的 scope，不能先成为 public 再要求角色假装不知道；未来决定不能写成初始事实。人物档案也是开场快照，不提前获得将来的发现或让步。

人物生成另收到已有阶段/规则的执行标签清单。`role` 是执行匹配标签，职业与社会身份仍由公开身份字段表达；生成器不能擅自换标签使规则无人可用，也不应把专用规则的完成效果复制到普通说话、拥抱等能力中。人物位置使用 `move_agent` 与人物位置条件，不用物品的 `entity_equals` 冒充人物位置。

效果中的 `$actor`、`$target`、`$value` 都产生字符串；`$value` 来自 `Intent.expected_effect`，不会自动解析成布尔值、数值或 JSON。世界生成前置校验会拒绝其写入非字符串字段，避免运行到角色决定时才反复失败；不同布尔选择须有明确同类型效果。局部修复携带实际数组索引清单，下标从零开始，不是规则 ID 中的数字。

V2 角色动作列表另展示其有权看到的规则效果摘要，标明是提交后才会登记的效果，帮助区分“开始往车走”和“提交已登车”。秘密世界字段、私密实体及尚未查验的知识不进入摘要；只展示当前规则实际使用的效果来源，不把 `effect_mode=ability` 中不执行的规则效果当成结果。这不是额外模型调用，也不代替执行校验。数值增量使用 `increment_world.amount`，`value` 不参与增减。

嵌套结束条件的实体引用错误在世界阶段就检查，并报告实际 JSON Pointer（包括 `conditions` 下标），不再只报告自动生成的子条件名称，避免修复器在人物姓名和人物 ID 之间反复换错目标。

## 修改时需要保持的边界

- “推进”是回答、验证、选择、行动或结果的变化；不等于制造新名词、新光效、冲突升级或提前宣布结局。
- 同一行动可以在战斗、修理、照护等场景合理重复，必须结合实际状态；不能只重说同一观点。
- 长段落的跨角色复述同样会被检查；真实消耗资源、移动或执行其他有效动作时，不因台词相似而拒绝整项行动。
- 没有新证据时允许保留分歧，不强迫人物坦白、不让人物凭空获得私密信息。
- 自定义规则用准确的 action_type / rule_id 表达；发言中的意图不能代替动作执行。
- V2 规则仍按 priority 选取，rule_id 不能绕过更高优先级规则；旧 V1 同动作的显式出口可以按 ID 选择。
- 听众不等于回应对象；明确点名的 specific 请求不会因动作里“看向大家”而变为全员待办。
- 回应甲时向乙提出新的问题或质疑，乙仍有自己的回应机会；只对原请求者的反问不自动形成嵌套强制问答。
- 固定名单中的演员不能由旁白增加；开放场景的背景人物不能变成新的可操控角色。
- 提示词不能替代执行校验。`runtime.py`、`narrative_grounding.py`、`dialogue_quality.py` 分别检查规则执行、部分结果证据和重复/信息边界。

## 当前合同的编排与人工审阅

默认演员仍是单次生成，不新增每回合导演或文风裁判请求。`actor.md` 管理职责、取舍、事实权限与提交边界，`dialogue.md` 管理相互交流、表达分量、人格与跨题材表演；后者的例子不是场景事实，不可直接引用。用户明确的古典、正式、冷硬、寡言或非人设定优先，不将所有题材现代口语化。

`build_agent_prompt` 的四条原生消息依次为：固定职责与表演合同；完整本人档案、人物选择倾向原文和有限视角事实、能力与当前合法动作；Intent 协议和实际事项登记参考；最新可见交流及本次任务。自动生成的 personality/decision_logic 不再重复放进 system，避免把倾向升级成每轮必须执行的脚本；原文完整保留，用户明确条件仍优先。事项图谱与数字不作为人物的首要写作任务。已知事实、原文回看和权限没有因重组而删除；较新事件优先于开场状态，不使人物逐轮回到初见。

人物生成的 `characters.md` 区分稳定人格、开场状态、主动愿望、已知事实、知情矩阵、表达偏好与接口对接。不将 `decision_logic` 生成成必走程序，不将软倾向升级为绝对禁令；信念不必填，主线之外的牵挂也不硬性分配。世界生成、人物生成与修复各有自己的任务，世界的执行合同不重复要求人物重新设计世界。

约束分析可将用户明确的禁止补写要求另编译为 `performance_policies`，与故事中的知情权限分开。固定 code 区分：不增背景人物、背景物品、背景数字、过去事实；以及范围更窄的不增金额、登场人物、隐藏缺陷、任务事项。只接受对应用户逐字原文的提取，未知 code 不进入上下文；角色与旁白只看到代码内置的通用规范，看不到原文、导演秘密或未来剧情，也不因此获得新知识。旧存档没有此字段时按空列表兼容，不自动猜测其创作限制。

这些 policy 是创作合同，不是事实核验器。逐字原文检查不能证明模型对禁止范围的解释正确；例如只限制登场人数，不应扩大成禁止所有背景联系人。没有明确限制的短输入仍允许在设定生成阶段合理补全，运行中的感受、主观判断与新计划也不被全面禁止。此路径不额外调用模型、不增加重试次数。

隐私检查发现可疑的新增认知、记忆或关系注释时，先剔除这项注释，不因辅助记账失败而丢弃本身合法的对白。公开 speech/action 仍经过原来的硬隐私门；此处理不将转述升级成已核验事实、不豁免隐藏信息，也不调用额外模型。保守词面检查仍可能剔除合理转述，真实可见原话保留在历史中，运行遥测只记录删除了哪些字段。终局 `all_eligible_acted` 阶段没有下一阶段、但存在适用结束规则时，继续分配真实角色回合直到实际结束条件满足，而不是全员说过话就阻塞；不虚构完成、不清空行动记录，也不改变有下一阶段的有限循环。

需要每人实际提交之后才推进的 `all_eligible_acted` 阶段可声明 `completion_action_types`。只对已提交、通过 Resolver 的这些动作计参与；说要上车、普通发言、未执行的草稿、别人重复登车都不能替另一人完成。参与从当前阶段的真实历史派生，不新增第二份持久化日志；检查点恢复、阶段重入按同一来源重建。空列表保留旧存档语义，不按动作名称擅自迁移已有场景。世界阶段检查动作许可与字段适用范围，人物齐备后检查每人的执行路径；此检查仍不证明任意复杂条件下均可完成。

世界生成与修复使用 `execution_design.md`，要求先核对“谁独立提交什么，能登记到哪一步”，然后仍只输出既有 JSON 字段，不新增可执行脚本。人物生成的 `_character_runtime_contract` 动态列出实际执行标签、阶段、效果来源、实体初值与结束依赖。多人独立确认优先通过各人固定键的能力效果与 `all_of` 表达，不通过一人调用总完成按钮代办全体；没有此需求的日常场景不强制签署流程。

`mechanics.action_context` 在能力驱动或叠加规则下另展示本人未耗尽、当前阶段可用的同类型能力及本人有权看到的实际效果。公共 `effect_mode=ability` 的 effects 不执行，不能展示成已执行结果或用于证明结束可达；被精确同目标范围的 rule-only 规则遮蔽、已耗尽或无合法阶段的能力效果也不作为完成来源。不同目标范围的复杂可达性仍作保守近似，校验不是通用语义证明。旧存档不会自动补出缺少的独立完成状态。

人工审阅建议先看 actor/dialogue 的表演要求，再看 characters 的生成要求，随后看 scenario/execution_design 的世界因果要求，最后核对各调用处的 JSON 协议。运行时实际发送的文本含动态资料，不能只审阅 Markdown；评测可将原生消息与代码/提示词摘要保存到本地忽略目录。不要将含私有档案、原始输入或供应商用量的评测快照提交公共仓库。

## 验证方法与限制

V2 世界规则可声明 `requires` 类型化执行前提（空数组兼容旧存档）：`world_equals(key,value)`、`entity_equals(target,key,value)`、`agent_location(target,value)`、`all_active_at_location(location)`，数组各项全部成立才执行。相等比较保持 JSON 类型，人物目标只支持 `$actor` 或本动作人物 `$target`；无脚本、表达式、嵌套布尔树或任意人物查询。生成、修复与人物接口清单同步此协议。Resolver 在效果和成本之前检查，失败不落入低优先级规则；检查点恢复保留原条件，V1 不能静默忽略非空前提。界面只显示有权限看到的条件，不显示私密条件值或私密真值，拒绝理由不包含秘密字段。成功/失败仍可能暴露操作是否可执行这一位信号；这是执行许可反馈，不宣称消除所有侧信道。能力的依赖通过同动作世界规则表达，能力自身不增加条件字段。

前提只解决“能不能执行”的硬依赖，不解决人物为什么选择、台词是否精彩或自然语言是否准确表演了实际执行。禁止以这一机制的通过率代替对话质量验收。

固定 `set_world` 效果在世界生成预检与最终包校验时使用和运行时相同的类型/allowed_values 规则；例如状态只允许“停靠/车内”，效果却写入“行驶中”，会在演员付费推演之前进入局部修复，而不是让演员反复重试永远不可执行的规则。不会自行扩大用户的状态白名单；复杂动态路径的全部可达性仍不由这一校验证明。

前提失败的定向纠错可附带演员有权限看到的所需状态与实际状态，例如本人已经抵达后不应重复提交要求在原地点的移动。动作清单也提前标明已知不满足的前提，不把带 `$target` 的未选目标条件提前猜测为失败；不展示其他地点人物的位置或私密状态值。公共旁白的 `narrator_facts` 包含当前公开实体状态及真实公开实体/世界效果，避免只看到准备动作或开场描述而推翻已结算结果。私密实体、知识、资源和私密事件仍不进入公共读回；语义表演与结果的完全一致性尚不能据此保证。

修改后同时检查：JSON 是否有效；实际动作及结算是否发生；跨多轮是否重复同一观点；是否引入未授权设定；未完成事项是否真正解决。不要以词汇差异、关系字段变化或进度条变化代替因果验证。

对话质量另看公开言行：是否回应眼前人的具体一句话，人物差异是否影响选择，私心是否全部变成公开分析，上次的态度是否被承接。短句、语气词、不同词汇和零重试都不能单独证明“活人感”。匿名评审的 `human_speech` 与 `character_specificity` 分别检查自然表达和人物选择差异，必须引用双方事件作为依据；单次模型评审仍有偏差，应与实际阅读、不同题材及重复运行的表现一起判断。

`actor_exchange` 使用角色可见的近期事件与个体观察，较旧的待回应来源也会补入；工作单只负责执行参考。历史发言是引用的场景数据，不伪装成当前模型自己的 assistant 历史。公开 speech 先生成，私密说明保持简短。没有事件依据的默认“平静”不作为强制心理状态，上次临时对话目标不覆盖完整人物目标；档案的“实验观察价值”保留在存档中，但不作为演员的动机注入。新人物生成同时补全与任务并存的具体牵挂，已有详细人设保持优先。

`simulation.conversation_recall` 默认 `linked`，可设为 `off` 回退近期窗口。`scenechat/conversation_recall.py` 从最近 160 个事件中先筛选本人可见的交流，再用回应链与词面相关度补入最多六条较旧原话，每位说话者最多两条、每条最多 500 字，并按原时间排列。个体观察替换原文时，不利用被遮蔽 Intent 的回应链选取历史。它不调用模型、不生成摘要、不创建待办、不改存档或人物知识；没有找到记录不表示事情未发生。词面检索不是语义证明，仍可能漏选或选入不相关的旧话。

显式空个体观察也表示原文被覆盖，不回退到完整原始事件；近期交流与较旧回看遵守同一边界。

回看的作用是让人物有机会承接“已经有人回答过什么”，不把回答当作真相，也不让所有人统一承认某个推理正确。`dialogue.md` 的家庭、争论和战斗对照示例分别展示未知细节如何留白、如何区分回答不足与从未回答、如何以当下选择而非虚构旧情表达关系。示例不提供可复用的人名或事实，不要求人人机智、合作或反对。

近期交流已完整呈现的同一观察，不再同时复制到观察列表和原始事件记忆里；只做精确文本与事件 ID 去重。较旧事件、未完整呈现的长观察、个体视角、私人反思、结构化承诺与认知纠错链仍保留。事项工作单记录来源、状态和证据，不向所有人物注入统一的核验/协商“下一步”；事项数据仍正常持久化，不替角色决定合作或拒绝。性格倾向不能作为虚构往事、伤情或检查结果的授权。

世界生成与局部修复共享运行协议：仅 `$actor`、`$target`、`$value` 三个完整占位符可用，不支持 `$world.xxx`、动态键或条件表达式。规则的自然语言描述不是执行条件。普通发言与有意选择的结束/提交操作应使用不同 `action_type` 并同步阶段许可；检测到高优先级特殊效果遮蔽同范围普通动作时，在生成角色之前报错修复，不通过降低 priority 绕过。这是结构检查，不是所有条件组合的可达性证明。

生成和修复引用同一份完整操作白名单。局部修复只返回 `changes`，格式重试保留具体失败路径与上一份无效补丁，不同时修改父路径和子路径；合法但无变化的补丁计入语义无进展次数，不误当作 JSON 错误再次循环。仅协议声明为任意 JSON 的效果值和结束/节点比较值允许修正 JSON 类型，普通字段类型、越界路径、身份与版本保护仍保持。纯机制问题使用世界与人物执行字段作为修复上下文，不让整份性格描写挤占补丁预算。组合结束条件 `all_of` 逐项检查更新来源或已满足的初始字面条件，不能因其中一项可更新就认为全体可完成；检查更新来源仍不等于形式化证明所有执行路径。

改提示词以代表性场景和实际输出为依据，不把“更短”“启用思考”或历史改成 assistant 消息当作必然优化。参考 [OpenAI 的模型优化与评测指南](https://developers.openai.com/api/docs/guides/model-optimization) 和 [Anthropic 的上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：减少冗余、保留关键上下文，并在不同任务与模型上验证。工程指标通过不证明对话已自然，也不能证明没有隐含的事实漂移。

演员与旁白均以真实 chat 消息区分职责、参考资料和当前输出要求：职责位于 system，历史仍是带来源的参考数据，不伪造 assistant 角色。旁白定向纠错追加消息，保留原职责与权限；换消息位置不能取代事实核验，也不保证所有模型都会遵循文风约束。

`scene` 是开场描述，不是每回合重置的物品和站位。角色、表演和旁白提示均明确这一点；检索资料内“当前状态”和档案中的“开局”也可能只是生成时的记录，不覆盖较新的已提交事件。现状依靠可见的后续事件和已提交状态。请求者在较旧议题上重新获得回合时，会看到原请求及近期回应，指令要求作出后续选择，而不是重新追问自己。普通取放、收拾或持续合作允许完成一个有意义的小步骤，但不能替他人作新决定或宣告规则结果。

由来源事件调度的接续回合不被周期性可选旁白打断，包括直接问题、被提及后的插话、请求者收到回应后的选择；模型漏填正式 obligation 不会让已经选定的接续回合被抢走。指定的真实阶段退出也不被常规旁白延迟。强制环境事件、规则结算和待应用的用户干预仍照常执行；这不是全局关闭旁白，也不推断未知的回应对象。多人已经给出相同观察时，不要求下一个人复报整份清单；未知、拒答、有限回应与当下感受都可以有内容，不以新增线索或强迫冲突制造差异。

公共旁白中显式标注的“镜头之外：”“仅供读者可见：”插入会被定向重试，不能借括号把包内屏幕或幕后反馈广播给人物。部分直接声明无人能看见的镜头位置（例如“从车厢内部无法看见的桥面上……”）也会检查；引号里的引用、单纯表示不知道和由视线外传来的声音、气味不按私密镜头拒绝。系统选定的 `audience_only` 镜头仍可呈现允许的读者信息；不自动改事件可见性来放行错误。这不是对所有隐含视角越界的语义识别。

人物初始知识需要写出本人掌握的事实内容，不只写“知道某信息”。未规定而可补全的细节在设定生成时确定，世界明确未知或用户禁止补全的事项仍保持未知；某人未知不等于所有人未知，私有内容不能复制到公开档案或对方知识中。人物知识内重复了公开背景的事实，不因为“确定知道”等 Markdown 字段标签而成为秘密；未知、怀疑与既有错误认知仍不被当成确定知识。

旧 Markdown 人物解析区分整数章节与子章节：`7.1` 可选核心信念不覆盖 `7.` 核心目标，未设定信念的说明不作为真实信念。结构化人物入口仍直接使用原始字段，不要求信念非空。评测版本指纹包含人物解析代码，以记录其对旧档案与信息边界检查的影响。

近期交流同时回读真正已提交且当前角色有权观察的投票、阶段切换、选票清空、移动，以及声明可见的世界/实体字段变化；不只看模型写的姿势或台词。个体观察覆盖原文时不补入完整 patch，私密选票不公开，任意私密状态或知识 patch 不作为对白附注输出。移动回读来自可观察事件，不通过全局查询公开其他角色当前位置。失败生成的台词不作为人物表现，但实际执行的安全规则结果仍可回读。当前阶段在交流末尾再次明确，专用执行选择不应只藏在 JSON 字段里。

人物目标是愿望，不是每轮待办；未登记完成不意味着没收到回应。人物生成保留倾向与开场状态的区别，不将“克制、容易追问、怕尴尬”擅自写成绝对禁令或唯一行动程序。表达画像的 avoidances 只用于明确的禁语与语境禁忌，不因性格自动禁止直接表达；用户明示的限制优先。

手动讨论阶段未填写 next_phase，但拥有唯一可执行、角色可见的 set_phase 出口，且该出口明确通向只允许专用选择动作的投票/行动阶段时，调度也可在既有节奏周期后提示使用真实出口。不会凭空造规则、替人物选分支、强制终局环境事件或限时结束开放聊天；最终仍由角色提交指定规则并经 Resolver 执行。退出校验使用该规则真实的目标阶段，不以缺失的 next_phase 误拒绝合法行动。

阵营结束条件必须绑定确实存在过的阵营，未知阵营不视为已全灭。阵营名称先精确匹配，再允许唯一的大小写等价匹配；若用户声明了仅大小写不同的两组阵营，仍保持两组独立。faction_parity 显式声明 opposing_factions 时只统计这些对立阵营，不把无关旁观者计入。生成校验检查嵌套结束条件中的阵营引用，旧运行检查点也适用这些判定保护，不修改人物原始阵营标签。

`config.json` 的 `simulation.actor_generation_mode` 默认 `single_pass`，每次角色反应仍只调用一次生成（失败重试另计）。可选 `performance_first` 先用 `performance.md` 与人物视角资料生成一次表演，再补执行字段；编码步骤只使用可见参考资料、合法接口、回应来源和原草稿，不再次要求角色重新表演。通常增加一次请求，由 `performance_max_tokens` 控制表演预算。它不是事后全员润色，也不允许修改其他人物或世界状态。无效或截断的表演草稿退回原单步 Intent 路径，不另开草稿重试循环；最终仍经过 Resolver、秘密与重复检查。失败定向重试允许修正不合法的草稿，而不是把错误台词锁死。全部请求共享既有时间和调用次数限制，并分别记为 `actor_performance`、`actor_intent`。

双阶段模式属于需评测的质量/成本选项，不保证比单步更好；启用前应在实际模型与题材上比较公开对话、因果、耗时及 token，而不是只看结构成功率。

## 可回退的场景质量实验选项

以下均在 `config.json` 的 `simulation` 中配置，不放入 `.env`。默认保留单步角色生成与周期性旁白；实验选项不是已证实更好的通用预设。修改后重启后端，已有存档无需迁移。

| 配置 | 默认 | 可选值与作用 |
| --- | --- | --- |
| `actor_prompt_style` | `classic` | `scene_first` 使用更精简的表演合同与人物视角资料；仍保留全部合法接口、私有知识和回应来源 |
| `scene_continuity_mode` | `off` | `evidence_log` 将角色提交动作中的可选原文注记带入后续角色与旁白上下文，不额外调用模型 |
| `intent_field_order` | `speech_first` | `action_first` 先选择本次真正执行的接口，再生成同一选择的公开表演；不自动替人物行动 |
| `action_grounding` | `off` | `rules` 在专用行动通过 Resolver 后额外检查动作文字与接口是否一致；明确失配进入既有一次质量重试 |
| `narrator_mode` | `periodic` | `actor_led` 只抑制常规可选旁白；必须的环境阶段、已确认导演引导和用户直接事件不受影响 |

`actor_led` 在多轮动作与等待场景中可能让进程更慢，不建议为减少旁白直接全局启用。`scene_first` 在部分人际场景能改善当场反应，但也可能产生更多静默和普通小动作；不同模型、题材需分别比较。

连续性记录实现位于 `scenechat/continuity.py`。`continuity_notes` 最多三条，对象名必须出现在引用中、引用必须逐字来自本次 `action`；从存档恢复后仍重新校验。按当前观察权限筛选，不公开私密动作或个体观察覆盖掉的原文。标签按原文匹配，不自动合并别名；模型漏记仍可能发生。它记录行为原文，不证明检查成功、承诺履行或外部反馈，不直接改变世界状态，也不使认知升级为 verified。

动作检查实现位于 `scenechat/action_grounding.py`，请求标记为 `actor_action_alignment`。普通 speak/act/observe/pass 不增加检查请求；专用动作通常多一次请求，纠正时可能再检查一次，全部共享现有操作超时与请求总上限。否定判断需引用当次表演原句；格式无效或引用不存在时记录 unknown/unsupported_rejection，不制造角色失败。模型判断仍可能漏判或误判，通过不意味着事实已核验；规则执行权限、资源消耗与结局仍由引擎决定。

人物生成不再重复叠加旧 Markdown 设计器。`characters.md` 同时规定精确人数/身份、公开私密边界和主动愿望；愿望进入已有 goals，不增加必填信念或预排下一轮台词。详细用户人设优先，不能以“增强互动”为由重写明确的寡言或疏离性格。对话合同允许连续追问改变人物的反应，也明确未知答案不需补成一份周全的信息清单。

上述模式的拼写在预检及恢复推演入口检查；无效配置在检索或付费调用前报错。匿名评测记录这些非敏感选项及相关代码摘要，以免把不同配置的结果混为同一版本。实测输出、模型用量与调试报告应保留在本地忽略目录，不提交公共仓库。

世界局部修复区分两种不可执行规则：只挂在 `event_only` 阶段，或挂在正常人物阶段但动作未列入 `allowed_action_types`。后者给出实际动作、当前许可与具体字段路径，修复指令要求同步两处，不靠反复重写原规则或只换阶段推进方式掩盖缺口。阶段切换生成示例采用独立自定义动作，避免与普通 act 混淆；不会自动扩大已有存档的行动权限。修复策略版本为 7，旧策略已停滞的生成检查点可按既有机制获得一次有预算的新修复周期。

只允许专用动作的选择阶段（例如表决、护卫或签署）另提醒：已经讨论过的共同理由可以简短跟随、表达自己的顾虑或沉默执行，不要求每个人重讲整段论证。仍须提交当前合法动作与目标；用户明确需要完整陈述时优先。此提示不自动剪掉台词、不替人物选目标，也不把安静选择算作生成失败。

`scenechat/dialogue_format.py` 在规则与质量检查之前，无额外模型调用地把 action 中明确的本人引号对白移回 speech。原句不润色，其他人的话、回忆、未说出口的计划、否定发言及不带引号的歧义文本不推断；不能依赖它识别所有文风错误。演员提示词同时要求全部对白写入 speech，避免补问留在动作里而影响回应追踪。

演员的事实边界包括自己的过去，不只包括别人的秘密：未知的日期、数额、已做检查和外部回应不能为了回答周全而补成既成事实。可以提出新打算、承认尚未核实，也允许不改变设定的称呼和当下小动作。旁白无新结果时跳过，不把普通等待切成连续感官描写；查找动作也不能自动证明某物不存在。以上是行为约束，并非通用事实验证器。

有动机的角色可以故意说谎、吹牛或遮掩，并在私密 `private_reason`（表演模式为 `thought`）说明是在编造。这是角色主张，不改真实档案、世界状态、知识或行动权限。没有欺骗动机时，不因被问到而补造真实往事；其他角色也不需要立即识破谎言。

`runtime.py` 对 `verified` 的执行证据更窄：对白事件中的任意关系/状态补丁不能核验整段台词。可见的实际投票/阶段回读，或明确授予本人的已提交知识，只有对应具体内容才能支持核验；否则保留为主观相信或听闻。非权威来源与生成兜底不提供核验证据，个体观察和私密范围继续隔离。此处不重写已有认知，也不是对所有旁白或自然语言主张的语义证明。

Intent 解析不把对象、数组或布尔值直接转成公开对白。单个 `{type, description}` 动作或其单元素列表可无损归一，嵌入执行效果、多个动作、类型冲突或不合法的 speech 走原有定向重试；空对象不补成虚假的观察事件。归一不会赋予新行动权限，不额外调用模型。

篇幅检查只作软提醒，不再以超过四句就要求重写；目前超过 480 字，或超过 240 字且多于八句时提示删掉重复铺垫。指标与运行时使用同一口径，评测版本为 `scenechat-quality-v7`。长度仍然不是自然表达或语义重复的证明，不应跨版本直接比较这一项分数。

`minimal_reply_share` 记录词面极简附和的占比、连续次数和事件 ID，帮助定位“嗯/行/好”的交换链；它不判行动是否推进、不计入质量总分，也不触发重试。无适用样本的指标不按零分处理；安全暂停、生成失败和轮次上限不算自然结束。实际人际意味和语义空转仍需阅读原始事件判断。

`silent_action_share` 另记录没有公开台词、显式状态补丁或已标记有效变化的普通行动区间，并给出事件 ID；旁白插入不会切断连续角色区间。安静陪伴或观察可能完全合理，因此这仍是诊断而不是失败判据，不触发强制发言、重试或自动结束。角色提示要求承接已经开始的完整步骤，并把实际规则尝试连接执行接口，不靠多轮准备姿势延长工序；这不授权模型宣布成功或替其他人物决定。

秘密检查保护隐藏身份、私有知识和世界声明的受保护命题；不把普通性格倾向当成新的隐藏物证。文本匹配按句子处理，不能把长段落中零散的常用字凑成泄密证据。自由文本旧档案仍采用兼容检查；这些启发式规则不能证明所有隐晦泄露都已被识别。

自动检查只能覆盖明确的结构、文本相似度和部分结果表达，不能保证理解所有语义等价或隐喻。旧存档里已经生成的错误剧情不会被自动重写；存在矛盾胜负规则的旧运行会明确报错，建议重新生成。

生成兜底不是角色真实拒绝、同意或犹豫。它保留错误计数、历史诊断及确已执行的安全规则效果，但不替角色生成台词，不关闭待回应问题，不更新人物情绪、关系或记忆；角色上下文中以系统失败提示呈现，不能据此推断人的态度。旧检查点中标记为 `generation_fallback` 的模板台词也不再作为角色回应重放。普通沉默与没有台词的真实行动不受此限制。

旧检查点中能按事件 ID 追溯到兜底的直接记忆、认知与含该事件的摘录不进入角色上下文，原始存档仍保留。已经经后续剧情产生的间接误解、没有来源记录的旧心理状态不能可靠自动撤销，不将这些过滤宣称为完整的旧故事修复。

匿名评审只有在两份样本都记录实际故事结束时才评价 ending；观察窗口截止、互道晚安或安全暂停不算已验收的结局，收尾项会标为 not_applicable。

投票回读依据已提交事件计算，并按可见性隔离；它不是给所有场景增加投票机制。自然语言中的票数、离场与身份公开检查仍是有限规则，不是通用语义证明器。一次受控场景通过也不代表开放剧情、复杂战斗和完整设定生成都已得到质量验证。

新一轮投票结果引用真实结算事件、通过票数/结果证据检查且尚未播报时，可免除广播句式的相似度误报；旧结果、伪造证据、错误票数、身份泄露和重复气氛不因此放行。角色结果的文本匹配不跨句或跨另一个姓名绑定，避免把“甲一票。乙被淘汰”误识别为甲也出局。

能力展示分别标明 `ability=<ID>` 与 `action_type=<类型>`，不把二者拼成一个引用。对于模型误填旧展示格式 `<ID>/<类型>`，或把动作类型填入 ability，只在本人的同类型能力唯一匹配时本地归一为 ID；未知引用和歧义不猜测。次数、阶段、目标与规则权限仍由 Resolver 校验，不因纠错获得新能力；定向重试也附带本人能力列表。此修复不额外调用模型。

提示词组织参考 [OpenAI 官方提示工程文档](https://developers.openai.com/api/docs/guides/prompt-engineering)：明确职责、约束、上下文与输出格式；实际效果仍须在所配置的模型上验证，不意味着更换为 OpenAI 模型。
